# Lotto-OP — 로또 6/45 추첨기

빌드·백엔드 없이 **단일 HTML 파일**로 동작하는 로또 6/45 추첨 시뮬레이터입니다. GitHub Gist 등 One-Page 호스팅에 바로 올려 쓸 수 있도록 CSS·JS를 모두 `index.html` 한 파일에 인라인으로 담았습니다.

**Live Demo:** https://wisemanlim.github.io/Lotto-OP/

## 실행 방법

- 별도 설치·빌드 없이 `index.html`을 브라우저로 열면 바로 동작합니다.
- Gist로 배포할 경우 `index.html` 파일 하나만 올리면 됩니다(외부 리소스 의존 없음).
- 로컬에서 확인하려면:
  ```bash
  open index.html          # macOS
  # 또는
  python3 -m http.server   # 임의 디렉터리에서 실행 후 브라우저 접속
  ```

## 추첨 로직

1. **추첨 시작** 클릭 시 1~45 범위를 Fisher–Yates로 섞어, 앞 6개를 당첨번호, 7번째를 보너스번호로 미리 확정합니다(진행 순서만 애니메이션).
2. 드럼 내부의 공은 매 프레임 난류성 랜덤 힘 + 소용돌이(vortex) 힘을 받아 계속 움직입니다(`physicsStep` → `stepBalls`).
   - **공 속도**: 슈트 우측 셀렉트(`#speedSel`)로 1x~3x 선택, 기본 **2.5x**. 1x가 이전 속도이며, 배율만큼 물리 시간을 빠르게 흘립니다. 빠른 공이 서로 겹쳐 통과하지 않도록 한 프레임을 `ceil(배율×2)`개 하위 스텝으로 나눠 계산합니다. 추첨 중에도 바로 바뀝니다.
3. 번호 1개를 뽑을 때마다 `extractBall()`이 실행됩니다:
   - 중앙 하단에서 기둥(`.pillar`)이 솟아오르며 해당 공을 구멍 쪽으로 들어 올림
   - 공이 드럼을 벗어나 슈트를 타고 하단 트레이 슬롯으로 낙하
   - 효과음(Web Audio API 오실레이터)과 함께 슬롯에 고정
4. 기본 당첨번호 6개 → 보너스번호 1개 순서로 반복되며, 완료 시 상태 메시지에 당첨번호 전체가 표시됩니다.

### 빠른 추첨

**빠른 추첨**(`quickDraw()`)은 동일한 Fisher–Yates 난수 로직을 쓰되, 기둥 상승·낙하 애니메이션을 건너뛰고 6개 번호 + 보너스번호를 트레이 슬롯에 즉시 배치합니다(`placeBallInstant()`). 당첨번호의 확률 분포는 **추첨 시작**과 완전히 동일하며, 소요 시간만 10여 초 → 즉시로 줄어듭니다.

- 이전 추첨 결과가 있으면 트레이와 드럼을 먼저 초기화한 뒤 새로 뽑습니다(연속 클릭 가능).
- 애니메이션 추첨이 진행 중일 때는 동작하지 않습니다.
- 등록된 게임 목록은 유지되고 등수만 초기화됩니다(**다시 추첨**과 동일).

## 당첨 등수 판정

`evaluateRank()` 기준 (실제 로또 6/45 규정과 동일):

| 등수 | 조건 | 확률 / 당첨금 |
|---|---|---|
| 1등 | 6개 번호 모두 일치 | 약 1 / 8,145,060 |
| 2등 | 5개 번호 일치 + 보너스 번호 일치 | 약 1 / 1,357,510 |
| 3등 | 5개 번호 일치 | 약 1 / 35,724 |
| 4등 | 4개 번호 일치 | 고정 50,000원 |
| 5등 | 3개 번호 일치 | 고정 5,000원 |

공이 나오는 **순서는 판정에 영향 없음** — 추첨 완료 후 번호 집합만으로 비교합니다.

## 내 번호 확인 / 게임 등록

- **게임 수**: 1 / 5 / 10게임 중 선택. 등록 가능 개수는 뱃지(`N / 목표 게임 등록`)로 표시됩니다.
- **수동 등록**: 번호판에서 6개를 고르고 **내 게임 등록** 클릭 → 화면에 게임 1건 추가.
- **랜덤 선택**: 클릭 한 번으로 남은 게임 수만큼 자동 생성 + 즉시 등록까지 완료.
- **게임 목록**: 각 게임은 한 줄에 번호 6개가 표시되며, ✕ 버튼으로 개별 삭제, **게임 전체 삭제**로 일괄 삭제 가능.
- 등록된 게임은 **화면(메모리)에서만 유지**되며 새로고침하면 초기화됩니다(localStorage 등 영속 저장 없음).
- 추첨 완료 후 **결과 확인**을 누르면 등록된 모든 게임을 당첨번호와 비교해 게임별 등수를 표시하고, 1~5등/낙첨 집계를 요약합니다.
- **즉시 게임 확인**: **게임 전체 삭제 → 랜덤 선택 → 결과 확인**을 한 번의 클릭으로 연속 실행합니다. 반복해서 누르면 매번 새 랜덤 게임으로 결과를 다시 확인할 수 있습니다. 추첨이 끝나지 않은 상태에서 누르면 게임만 등록되고 "먼저 추첨을 진행하세요" 안내가 표시됩니다.
- **다시 추첨**을 누르면 드럼과 트레이만 초기화되고, 등록된 게임 목록은 유지됩니다(등수만 초기화).

## 희망등수까지 추첨 (시뮬레이션)

**희망등수**(1~5등)를 고르고 **N등까지 추첨**을 누르면, 목표 등수가 나올 때까지 게임 구매를 반복해 **총 몇 게임이 필요한지** 측정합니다. 조작 요소는 게임 목록 바로 위 시뮬레이션 바에 있습니다.

- **당첨번호는 화면에 이미 확정된 번호(추첨 시작 / 빠른 추첨 결과)를 그대로 사용**합니다. 매 회차마다 새로 뽑지 않습니다. 추첨 전에 누르면 "먼저 추첨을 진행하세요" 안내만 표시하고 시작하지 않습니다.
- **1회차** = 선택한 게임 수(1/5/10)만큼 랜덤 게임을 새로 사서 판정.
- **총 게임 수 = 회차 × 게임 수**. 버튼 우측 뱃지에 `총 00게임`이 실시간으로 올라가고, 결과 영역에는 `N등 목표 · 추첨 중 — 00회차 × 00게임 = 총 00게임 · 00초`가 함께 갱신됩니다.
- 뱃지는 시작할 때 `총 0게임`으로 초기화되고, 목표 달성·중지 시점의 값에서 멈춥니다.
- 목표 등수 **이상**(예: 2등 목표일 때 1등도 종료 조건)을 달성하면 멈추고, **당첨이 나온 마지막 회차의 게임 N벌을 게임 목록에 올려** 등수와 함께 보여줍니다. 추첨기 트레이의 당첨번호는 바뀌지 않습니다.
- 실행 중에는 버튼 라벨이 **N등까지 추첨 중지**로 바뀌며, 다시 누르면 즉시 중단하고 그때까지의 회차·게임 수를 표시합니다.
- 실행 중에는 다른 버튼과 게임 수·희망등수·함께추첨할 등수 선택이 잠깁니다(중단 시 이전 상태로 복원).

### 함께추첨할 등수

- 셀렉트 옵션은 **희망등수에 따라 동적으로** 바뀝니다: `-`(선택 안함) + 희망등수를 제외한 1~5등. 예) 희망등수 3등 → `- / 1등 / 2등 / 4등 / 5등`. 선택 안함을 `-`로 표기해 희망등수 셀렉트와 가로 폭을 맞췄습니다.
- 희망등수를 바꿔 현재 함께추첨할 등수와 같아지면 `-`로 초기화됩니다. 기본값은 `-`(기존 동작과 동일).
- 선택하면 **같은 회차(게임 N벌) 안에서** 희망등수 게임과 함께추첨할 등수 게임이 **서로 다른 게임으로 동시에** 나올 때까지 추첨을 계속합니다. 다른 회차에서 각각 나온 것은 달성으로 보지 않습니다.
- 희망등수는 기존처럼 **그 등수 이상**, 함께추첨할 등수는 **정확히 그 등수**가 나와야 합니다.
- 한 게임은 하나의 등수만 가지므로 **1게임 설정에서는 함께추첨할 등수를 쓸 수 없습니다**(시작 시 안내 메시지 표시).
- 달성 시 결과 영역에 `1등 목표 → 1등 · 3번째 게임 · 4등 목표 → 4등 · 7번째 게임`처럼 회차 내 위치를 표시하고, 그 회차의 게임 N벌을 게임 목록에 올립니다.
- 참고 — 1등 + 4등(10게임)은 1등이 나온 회차 중 약 0.9%만 4등을 함께 포함하므로 기대 게임 수가 약 9억 게임 이상이라 수 분이 걸릴 수 있습니다.

### 구현 메모

- 시뮬레이션 루프는 **DOM을 전혀 건드리지 않고** 숫자 연산만 수행합니다(`simRound()`). 번호 생성은 전체 셔플 대신 앞 6개만 섞는 **부분 Fisher–Yates**(`pickInto()`)를 씁니다.
- 24ms 단위로 끊어 `setTimeout`에 양보하므로 수백만 회차를 돌려도 화면이 멈추지 않고 중지 버튼이 즉시 반응합니다.
- `simRound()`는 회차마다 희망등수·함께추첨 달성 게임을 새로 찾고, 같은 회차에서 둘 다 찾으면(함께추첨 미선택 시 희망등수만) 남은 게임을 채운 뒤 `sim.targetHit` / `sim.companionHit`(`{rank, game}`)에 기록하고 종료합니다. 옵션 목록은 `buildCompanionOptions()`가 희망등수 변경 시마다 다시 만듭니다.
- 등수 판정은 `simRankOf(일치수, 보너스일치)`로, 화면용 `evaluateRank()`와 동일한 규정을 따릅니다. 당첨번호가 고정이므로 포함 여부는 `simStart()`에서 한 번만 만든 `Uint8Array`(`simMark`) 조회로 끝납니다.
- 참고 — 1등 기대 게임 수는 약 814만 게임(1 / 8,145,060)이라 보통 수 초가 걸리고, 운에 따라 수십 초까지 길어질 수 있습니다. 5등(3개 일치)은 보통 수백 게임 안에 끝납니다.

## 커스터마이징 포인트

- `index.html` 상단 `<style>` 내 `:root` 변수로 색상 테마 변경 가능.
- 드럼 크기: `.drum-frame` width/height와 스크립트의 `DRUM_R`(드럼 반지름), `renderBall()`의 `cx, cy`(중심 좌표)를 함께 조정해야 합니다(세 값이 서로 연동됨).
- 공 크기: `.ball` width/height와 스크립트의 `BALL_R`(반지름)을 함께 바꾸고, `.slot`(트레이 칸)·`.hole`(구멍)·`.pillar` 폭도 비율에 맞춰 조정합니다(현재 공 44px · 칸 48px · 구멍 50px · 기둥 51px).
- 공 속도 선택지: `#speedSel`의 `<option>` 값(물리 시간 배율)을 수정합니다.
- 공 개수/범위를 바꾸려면 `TOTAL` 상수와 `colorGroup()` 구간 기준을 함께 수정해야 합니다.
- 추첨 속도: `startDraw()` 내 `sleep()` 호출 간격, `extractBall()` 내 3단계 애니메이션 시간(정렬 0.2s → 기둥 상승 0.68s → 낙하 0.5s, 각 `setTimeout` 값과 CSS transition 값을 함께 변경)으로 조절합니다.
- 기둥 두께/높이: `.pillar`의 `width`와 `extractBall()`의 `RISE_H`(목표 높이)를 함께 조정합니다.

## 제한 사항

- 순수 프런트엔드 데모이며, 실제 로또 추첨 결과·당첨 사실과는 무관합니다.
- 서버/DB가 없으므로 등록한 게임·추첨 이력은 저장되지 않고 새로고침 시 사라집니다.
- 난수는 `Math.random()` 기반으로, 암호학적 안전성이 필요한 용도에는 적합하지 않습니다.

### 접속이 안 될 때 점검 순서

1. **저장소가 Public인지 확인** — Private 저장소는 GitHub Free 플랜에서 Pages를 외부 공개할 수 없습니다(Pro 이상 필요). 이 저장소는 Public이라 해당 없음.
2. **루트에 `index.html`이 있는지 확인** — 파일명이 `index.html`(소문자)이어야 자동으로 루트 페이지로 서빙됩니다.
3. **Settings → Pages에서 배포 상태 확인** — `Your site is live at ...` 문구가 없고 빌드 이력이 비어 있다면, **Pages 설정만 저장되고 실제 빌드가 한 번도 실행되지 않은 상태**입니다(Source를 지정하는 것과 사이트를 실제로 빌드/배포하는 것은 별개 이벤트입니다).
4. **최초 빌드 미실행이 가장 흔한 원인**입니다 — 코드를 먼저 push하고 Pages 설정을 나중에 켠 경우, 설정 저장 시점에 빌드가 자동으로 걸리지 않을 수 있습니다. 이 경우 **`main` 브랜치에 새 커밋을 아무거나 push**하면 내부적으로 빌드가 트리거됩니다. (본 저장소도 이 문제였습니다 — 아래 "실제 발생 사례" 참고)
5. 그래도 안 되면 Settings → Pages에서 Branch를 한 번 `None`으로 바꿔 Save한 뒤, 다시 `main`/`root`로 바꿔 Save — 강제로 재빌드를 유도합니다.
6. 반영까지 보통 수십 초~수 분 걸릴 수 있으니, 브라우저 강력 새로고침(캐시 무시) 후 재확인.
7. 커스텀 도메인(CNAME)을 쓰지 않는 한 `https://<계정>.github.io/<저장소명>/` 형태 URL만 유효합니다. 저장소명 대소문자·오탈자를 다시 확인하세요.
